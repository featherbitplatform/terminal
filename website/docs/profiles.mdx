A profile describes one thing a tab can open: a local program or an SSH connection. Profiles live in `profiles.toml` in the [configuration directory](files). You can edit them in the app (`Cmd+Shift+,`, or `Ctrl+Shift+,` on Linux and Windows) or by hand; the app reloads the file when it changes.

The file is a list of `[[profiles]]` tables. Shells found in `/etc/shells` are offered automatically and are not written to the file. On macOS and Linux they start as login shells (`-l`), so your shell profile sets `PATH` even when the app was opened from the Dock or Finder. A local session that inherits no locale (none of `LANG`, `LC_ALL` or `LC_CTYPE`, and the profile sets none) gets `LANG=en_US.UTF-8` on macOS and `LANG=C.UTF-8` on Linux.

## Fields common to every profile

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `id` | string (UUID) | yes | Stable identifier. Other profiles and `state.toml` refer to it. Never reuse or change it. |
| `name` | string | yes | Name shown in tabs and the palette. Must be unique. |
| `kind` | `"local"` or `"ssh"` | yes | Selects which of the fields below apply. |
| `group` | string | no | Free-form group label. |
| `accent` | string | no | Tab accent color as `"#rrggbb"` (six hex digits, with the leading `#`). |
| `accent_style` | `"stripe"` or `"tab"` | no | How the accent shows on tabs (see [Tab colors](#tab-colors)). Default `"stripe"`, which is not written to the file. |
| `color_scheme` | string | no | Id of the [color scheme](color-schemes) for this profile's sessions; without it the global scheme applies. In the profile editor, the **Color scheme** field with **Use global scheme** as its first choice. |

### Tab colors

A profile with an `accent` marks its tabs in one of two ways, chosen with **Color as** next to the accent picker in the profile editor:

- **Stripe** (default): a thin bar of the accent at the left of the tab.
- **Whole tab**: the tab is tinted with the accent. Tabs in the background get a light tint (a little stronger under the pointer); the active tab gets a stronger one that fades into the terminal's background, so it still reads as one surface with the terminal below it. The tab's text switches between light and dark to stay readable on the tint.

Without an accent, both look the same: a plain tab. The tint follows the background opacity like the rest of the tab bar.

## Duplicating a profile

**Duplicate** at the bottom of the profile editor saves a copy of the selected profile at once and opens it, with the name field ready for a new name. The palette action **Duplicate profile** does the same for the focused pane's profile (in the profile editor, for the selected one) and opens the editor on the copy. When the focused pane's profile is no longer saved, nothing is copied and the editor says `Select a profile, then choose Duplicate.` The action has no shortcut by default and can be given one as `duplicate_profile` (see [Keyboard shortcuts](keyboard-shortcuts#the-keys-table)).

The copy gets a new `id` and every other setting of the original: group, accent, color scheme, host, port, user, authentication and key path, jump hosts and tunnels, or the program, arguments, working directory and environment of a local profile. Only the name changes: `<name> copy`, or `<name> copy 2`, `<name> copy 3` and so on when that name is taken. It is listed right after the original.

The copy also gets the original's [saved](saved-secrets) password or key passphrase. When they are in a locked vault, **Unlock saved secrets** asks first; cancelling still makes the copy, without them, and the editor says `Duplicated without its saved secrets: they are locked.` While those secrets are being saved for the copy, the editor shows `Duplicating…`, and **Duplicate** and **Save** wait until it is done.

Duplicate copies the saved profile, so it is refused while the editor has unsaved changes (`Unsaved changes: save or discard them before duplicating.`), and while `profiles.toml` cannot be read.

## Local profiles (`kind = "local"`)

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `program` | path | required | Program to run, such as `/bin/zsh`. |
| `args` | array of strings | `[]` | Arguments. |
| `cwd` | path | the app's default | Working directory. |
| `env` | table of strings | `{}` | Extra environment variables. |

## SSH profiles (`kind = "ssh"`)

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `host` | string | required | Host name or address. Must not be empty. |
| `port` | integer | `22` | TCP port. |
| `user` | string | required | User to log in as. |
| `auth` | table | required | How to authenticate; see below. |
| `jump` | array of profile ids | `[]` | Profiles to hop through before this one. |
| `tunnels` | array of tables | `[]` | Named port forwards and SOCKS proxies that ride this profile's connection, written as `[[profiles.tunnels]]` tables right after the profile. See [Tunnels](tunnels#in-profilestoml). |

### Authentication

`auth` is a table whose `type` selects the method:

| Form | Meaning |
| --- | --- |
| `auth = { type = "password" }` | Ask for a password. The app can remember it in the system keychain or the encrypted vault. |
| `auth = { type = "key", path = "~/.ssh/id_ed25519" }` | Use a private key file. A leading `~` is your home directory. |
| `auth = { type = "key", path = "~/.ssh/id_ed25519", passphrase = true }` | Same, and the key has a passphrase. `passphrase` defaults to `false`. |
| `auth = { type = "key" }` | A private key file not chosen yet. Connecting asks you to choose it (`Choose the private key for {profile}`, opening in `~/.ssh`), and once the server accepts the key the file is written into the profile as its `path`. |
| `auth = { type = "agent" }` | Use the running SSH agent. |

In the profile editor, leaving the private key field empty saves a key profile without a `path`. A profile can also arrive without a key file in an [imported archive](export-import). The chosen file is kept in memory only, until the app quits and you are asked again next time, when `profiles.toml` cannot be read, cannot be written, or was edited on disk and not reloaded yet (writing then would overwrite your edit). Automatic reconnects and tunnels restarting in the background never ask: they stop with "needs your input" until you connect the profile once yourself.

A key file must be a regular file of at most 1 MB; anything else (a folder, a device, a link to one) is refused with `The key file {path} is not a regular file.` or `The key file {path} is too large to be a private key.`

When a login uses an RSA private key (from a key file or the SSH agent), the profile editor and the tab show a one-line warning suggesting an ed25519 key (`ssh-keygen -t ed25519`); the connection still works. Verifying a server's RSA host key does not warn.

The file never contains a password or a passphrase. The `passphrase = true` flag only records that the key has one; it is set for you when you connect, type the key's passphrase and ask to remember it. The values themselves are kept where [saved secrets](saved-secrets) live (the system keychain or an encrypted vault), or asked for when you connect.

### Host keys

Host keys are checked against `~/.ssh/known_hosts`, the same file OpenSSH uses. The first time you connect to a host you are asked whether to trust its key, and a trusted key is added to the file. If a host presents a different key than the one recorded, the connection is refused with a message that the host key has changed; remove the old entry from `known_hosts` if the server was reinstalled. Host certificates (`@cert-authority`) are not supported.

## Jump hosts

`jump` lists the profiles to pass through, in connection order, then the profile itself is the final hop. Each entry is the `id` of another SSH profile.

In the example, `api-1` has `jump = ["0b8a6c52-..."]`, which is `bastion`. Opening `api-1` connects to `bastion`, then from `bastion` to `api-1`.

You can chain in two ways, and they combine:

- **Several ids in one `jump`.** `jump = [a, b]` connects to `a`, then `b`, then the target.
- **A hop that has its own `jump`.** In the example, `db-1` jumps through `api-1`, which itself jumps through `bastion`. Opening `db-1` connects `bastion`, then `api-1`, then `db-1`. A hop's own jumps are expanded first.

A profile may go through at most 32 jump hosts once every hop's own jumps are expanded; real chains are a handful. Each hop authenticates with its own profile, so every hop needs a working `auth`. Tabs that share a hop reuse its connection, so opening a second host behind `bastion` does not log in to `bastion` again. [Tunnels](tunnels) ride the same connection and its jump chain.

## Validation

The app validates `profiles.toml` when it loads it. Each problem is shown as a notice that starts with the file path.

| Problem | Message |
| --- | --- |
| Two profiles share a name | `duplicate profile name "<name>"` |
| `jump` names an id that does not exist | `profile "<name>" jumps through unknown profile <id>` |
| `jump` names a local profile | `profile "<name>" jumps through a non-SSH profile` |
| Profiles jump through each other in a loop | `profile "<name>" has a jump cycle` |
| A profile goes through more than 32 jump hosts (expanded) | `profile "<name>" goes through more than 32 jump hosts` |
| `host` is empty or blank | `profile "<name>" has an empty host` |
| A tunnel has no name, or two tunnels of a profile share one | `profile "<name>" has a tunnel without a name`, `profile "<name>" has two tunnels named "<tunnel>"` |
| A `local` or `socks` tunnel has port `0`, a tunnel has no target port, or an empty bind address or host | `tunnel "<tunnel>" of profile "<name>" needs a port above 0` and similar |

A file with a jump chain that is too long still loads, and shows the notice; the profile editor will not save until the chain is shortened.

A file that is not valid TOML, or has a bad value (for example `accent = "red"`, which must be `"#rrggbb"`), is reported with its path and line number, for example `profiles.toml:12: invalid colour "red": expected "#rrggbb"`. A malformed file is never modified or overwritten, and profiles are read-only until you fix it.
