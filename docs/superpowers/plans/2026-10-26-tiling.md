# Tiling (split panes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split a tab into resizable, rearrangeable panes, each its own session, with per-pane zoom, keyboard handling, search across panes, and restore on relaunch.

**Architecture:** A pure layout tree (`layout.rs`) owns geometry and every rearrangement. `Tab` keeps its identity and becomes a container of `Pane`s (the per-session fields move from `Tab` to `Pane`). The window view renders the active tab through a custom `Tiles` widget that places one terminal widget per pane at the rectangles the tree computes, draws dividers, focus outline and dimming, and turns mouse input on dividers, handles and drop targets into messages. Everything keyed by tab today (`Message::Terminal`, connect results, find, pacing, release) is re-keyed by pane.

**Tech Stack:** Rust 2024, iced 0.14 (daemon, `advanced` feature for the custom widget), feathercritty, existing fbterm crates.

**Spec:** `docs/superpowers/specs/2026-10-26-tiling-design.md` (refines `2026-10-23-featherbit-terminal-design.md` 5.3, 5.5, 5.6, 5.11). Code map used for this plan: tabs.rs, sessions.rs, windows.rs, window.rs, find/, palette.rs, keys (fbterm-config), restore.rs, state.rs.

## Global Constraints

- A tab with one pane looks and behaves exactly as today: no outline, no dimming, no handle, same shortcuts, same restore of an old `state.toml`.
- Redraw contract (`CLAUDE.md`): call `take_dirty` before locking a terminal to draw; only panes of the visible tab of a visible window take the flag; no periodic subscription or redraw loop; output stays paced per session by `Pacer`.
- No host side effects from remote programs; `memory::release_freed()` only after user actions (closing a pane, tab or window, lowering scrollback).
- No new `unsafe`. Cross-platform: macOS, Linux, Windows build and test; platform code behind `cfg`.
- Product copy: no emoji, no em-dashes; never name another terminal application. Graphite look: colors only from the theme tokens (`theme.rs`, `Tokens`), never a hard-coded new hue.
- Conventional Commits; no attribution of any kind (no `Co-Authored-By`, no `Claude-Session`, no claude.ai links).
- Gates per task: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Copy (exact): close confirmation title `Close this tab?`, body `Its {n} panes and their sessions will close.`, buttons `Close tab` and `Cancel`; palette hint `Shift+Enter opens in a split`; palette action labels `Split right`, `Split down`, `Maximize pane`, `Find in this tab`, `Merge tab into…`, `Move tile…`, `Move tile to new tab`.

## Review Focus

1. Splitting until a pane hits the minimum size: the split is refused (no zero-size pane, no panic), the user sees nothing break. Test in Task 1 (`split_refused_below_minimum`).
2. A pane's session ends or disconnects while another pane is focused: the right pane gets the notice, the tab shows the background indicator, input still goes to the focused pane. Test in Task 2 (`events_reach_their_pane`) and Task 8 (`tab_shows_trouble_in_background_pane`).
3. Closing the focused pane while a find bar, export or find-all result points at it: no stale pane id is used later (jump to a closed pane does nothing). Test in Task 7 (`jump_to_closed_pane_is_ignored`).
4. A `state.toml` from 0.1.0 (flat `tabs = [uuid, …]`) and one with a split whose profile was deleted: both load; the deleted profile's pane is dropped and its sibling takes the space; a tab left with no panes is dropped. Test in Task 5 (`old_state_loads_as_single_panes`, `deleted_profile_drops_its_pane`).
5. Dragging a divider across a pane with a running full-screen program: the program gets a bounded number of resizes (debounced), and the final size is exact. Test in Task 3 (`divider_drag_debounces_session_resize`).

### Task 1: Pure layout tree

**Files:**
- Create: `crates/fbterm/src/layout.rs` (register in `main.rs`)

**Interfaces:**
- Produces:
  - `pub struct PaneId(pub u64)` with `PaneId::next()` (atomic counter, like `TabId::next`, `tabs.rs:14`); derives `Debug, Clone, Copy, PartialEq, Eq, Hash, Ord, PartialOrd`.
  - `pub enum Axis { Row, Column }` (Row = children side by side, Column = stacked).
  - `pub enum Side { Left, Right, Top, Bottom }`, `pub enum Dir { Left, Right, Up, Down }`.
  - `pub enum Layout { Pane(PaneId), Split { axis: Axis, ratio: f32, first: Box<Layout>, second: Box<Layout> } }` (`ratio` = share of `first`, in `0.0..1.0`); derives `Debug, Clone, PartialEq`.
  - `pub enum Drop { Tile(PaneId, Side), Edge(Side) }` (where an inserted subtree lands).
  - `pub type Path = Vec<bool>` (from the root: `false` = first, `true` = second) naming a split.
  - `pub struct Divider { pub path: Path, pub axis: Axis, pub rect: iced::Rectangle }`.
  - `pub const MIN_COLS: u16 = 20; pub const MIN_ROWS: u16 = 5; pub const DIVIDER: f32 = 4.0;` (logical px; the divider's visible line is 1 px centred, the rest is hit area).
  - Methods on `Layout`: `panes(&self) -> Vec<PaneId>` (reading order), `contains(PaneId) -> bool`, `split(&mut self, target: PaneId, side: Side, new: PaneId)`, `insert(&mut self, subtree: Layout, at: Drop)`, `remove(&mut self, pane: PaneId) -> Option<Layout>` (returns the removed leaf; the sibling takes the parent's place; `None` if absent; removing the last pane is the caller's job), `move_pane(&mut self, pane: PaneId, at: Drop) -> bool`, `rects(&self, area: Rectangle) -> Vec<(PaneId, Rectangle)>`, `dividers(&self, area: Rectangle) -> Vec<Divider>`, `set_ratio(&mut self, path: &Path, ratio: f32)`, `equalize(&mut self, path: &Path)`, `neighbour(&self, area: Rectangle, from: PaneId, dir: Dir, recent: &[PaneId]) -> Option<PaneId>`, `fits(&self, area: Rectangle, cell: Size) -> bool` (every pane ≥ `MIN_COLS`×`MIN_ROWS` cells).
  - `insert` with `Drop::Edge(side)`: the subtree becomes a new root split with the old root, the subtree taking `1 / (n + 1)` of the axis where `n` is the number of top-level siblings along that axis (existing tiles shrink proportionally). `Drop::Tile(p, side)`: `p`'s leaf becomes a split of `p` and the subtree, ratio `0.5`, subtree on `side`.
  - `neighbour`: candidates are panes whose rect lies in `dir` from `from` and overlap on the other axis; pick the nearest edge; ties go to the earliest in `recent`, then reading order.
  - `set_ratio` clamps so neither side goes below the minimum the caller checks with `fits`; ratios are clamped to `0.05..=0.95`.
